## 🔒 安全优先的开发计划

基于你的安全考虑，我重新设计了开发计划：

### 阶段 0：安全与备份基础设施（2周）⭐ **最高优先级**

**在进行任何数据库操作前，先建立完善的安全机制：**

#### 1. 备份模块 (`backup/`)
- 自动创建数据库备份
- 验证备份完整性（能否打开、哈希是否正确）
- 备份策略：默认保留 5 个备份，自动清理旧备份
- 恢复机制：失败时自动回滚

#### 2. 哈希一致性模块 (`hash/`)
- 管理 `files/` 目录中的哈希文件
- 验证 Realm 引用与实际文件的一致性
- 检测孤立文件（有文件但无引用）
- 检测丢失文件（有引用但无文件）

#### 3. 安全操作框架 (`safety/`)
- **RAII 模式的安全守卫：**
  ```rust
  {
      let _guard = SafetyGuard::new(db.path())?;
      // 执行危险操作
      operation()?;
      _guard.commit(); // 成功才提交
  } // 失败时 Drop 自动恢复备份
  ```

- **安全操作包装器：**
  ```rust
  safe_operation(&db, |db| {
      operations::beatmap::delete(db, id)?;
      Ok(())
  })?; // 失败自动回滚
  ```

### 关键安全原则

#### 🔴 原则1：永不信任自己
所有写操作都假设可能失败，必须有回滚机制。

#### 🔴 原则2：Realm + 哈希双重一致性
```
删除操作：先删 Realm 引用 → 确认成功 → 再删文件
添加操作：先写文件 → 计算哈希 → 再建引用
```

**为什么？** 如果反过来：
- 先删文件再删引用，中间崩溃 → osu! 找不到文件 → 崩溃 ❌
- 先删引用再删文件，中间崩溃 → 只是孤立文件，不影响使用 ✅

#### 🔴 原则3：操作前必须备份
```rust
pub fn safe_operation<T, F>(db: &RealmDatabase, operation: F) -> Result<T> {
    // 1. 创建备份
    let backup = db.create_backup()?;
    
    // 2. 验证备份
    backup.verify()?;
    
    // 3. 执行操作
    let result = operation(db);
    
    match result {
        Ok(value) => {
            // 4. 验证完整性
            db.verify_integrity()?;
            Ok(value)
        }
        Err(e) => {
            // 5. 失败：恢复
            backup.restore()?;
            Err(e)
        }
    }
}
```

## 💡 关键洞察

### 为什么先实现备份？

因为 osu!lazer 的双层架构（Realm + 哈希存储）非常容易因为操作不当而损坏：
- Realm 记录文件引用
- 文件实际存储在 files/ 目录
- 两者必须保持同步

**任何不一致都会导致：**
- osu! 无法启动
- 用户丢失所有游戏数据
- 无法恢复

所以**必须先有备份和恢复机制**，再进行任何写操作。
